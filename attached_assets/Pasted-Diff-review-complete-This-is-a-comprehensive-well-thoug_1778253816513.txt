## Concern 1 — Duplicate `createOrder` logic (real, fixable)

In Replit's Edit 2, the new `createOrder` callback inside `createCardFieldsOneTimePaymentSession({...})` duplicates what the existing standalone `createOrder()` function (lines 52-77) already does. They're now two near-identical implementations of "POST to /paypal/order with cart items."

**Why this matters:** in 5e we add `payment_source.card`, shipping address, and `PayPal-Request-Id` to the order creation flow. If we have two implementations of `createOrder`, we have to remember to update both. Easy to miss one and end up with subtle bugs where card orders get the new fields but PayPal orders don't (or vice versa).

**Fix:** Have the v6 inline callback call the existing standalone `createOrder()` function:

```js
createOrder: async () => {
  const result = await createOrder();
  return result.orderId; // unwrap to plain string for v6
},
```

This way 5e only has to update one place. Replit even noted "the standalone createOrder function on lines 52–77 is no longer called anywhere after 5c" — so they were aware of the duplication. Just consolidate now.

## Concern 2 — PayPal popup button conflict (real, ambiguous)

The user clicks the top-level Card button → checkout.tsx renders `<PayPalCheckout defaultMethod="card" />` → PayPalCheckout's internal `selectedMethod` is "card" → card fields render.

**But what about the existing PayPal popup button INSIDE PayPalCheckout?** Replit's spec answer (D) said:
> "Pay button: Visible when cardFieldsReady, disabled in 5c... No PayPal popup button shown when card tab active."

The diff doesn't show the JSX rendering logic for the PayPal popup button — just the card fields section. I want to verify that when `selectedMethod === "card"`, the "Pay with PayPal" button (the one that fires `handlePayPalClick` to launch the popup) is **hidden**, not just visually de-emphasized.

If both buttons render simultaneously, the user sees a confusing two-button area: yellow PAY $XX.XX (card) and the PayPal-blue button. They'd wonder which to click.

**Fix:** Replit needs to confirm the PayPal popup button is gated behind `selectedMethod === "paypal"` — invisible when Card is the active tab.

## Smaller flag (non-blocking)

Not worth fixing now — only happens in dev StrictMode, doesn't affect production. Just flagging.
