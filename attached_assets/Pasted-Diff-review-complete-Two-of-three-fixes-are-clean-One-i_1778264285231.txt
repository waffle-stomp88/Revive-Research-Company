## What's WRONG — Issue 2 fix has a real problem

Replit proposed:
```
className="h-12 bg-[#0a0a0a] border border-border rounded-md focus-within:border-[#d4ed1f] overflow-hidden"
```

**The `overflow-hidden` is a problem.**

Here's why: PayPal v6 card iframes can render TWO things vertically:
1. The input itself (~40px)
2. **An inline error message below it** when validation fails (e.g., "Card number is invalid", "Expiry must be in the future")

The error messages render INSIDE the iframe, below the input. With `h-12 overflow-hidden`, those error messages get clipped — invisible to the user. The user types an invalid card number, gets no feedback, doesn't know what's wrong.

This is the SAME concern I raised earlier about the "fixed height to clip" approach being a hack. Replit even acknowledged this in their note:

> "If PayPal's sandbox also ignores '#0a0a0a' on body, then the h-12 overflow-hidden from Issue 2 becomes the effective fix — it clips the white body to exactly the 48px visible area"

That's not a fix — that's a hack that breaks error UX. We rejected this approach earlier.

## The right fix for Issue 2

The fields are too tall because the iframe is growing too tall, NOT because the wrapper is. Fix the iframe, not the wrapper.

Options to investigate, in order:

1. **Check the placeholder value** — long placeholder text might be causing PayPal to allocate extra padding. Try shortening:
   - "1234 1234 1234 1234" → "Card number" (or shorter)
   - "MM / YY" → "MM/YY" (no spaces)

2. **Check the style padding** — current style has `padding: "0 12px"`. If PayPal interprets that as `0` vertical + `12px` horizontal, the input itself should be tight. But if there's also an outer wrapper PayPal adds with its own padding, that compounds.

3. **Look at the actual rendered iframe in DevTools** — inspect the iframe element, see what `height` PayPal is setting. That tells us where the bloat comes from. Replit can do this without applying the diff.

4. **Try `min-h-[44px]` (not `h-12`) on the wrapper** — gives the iframe room to grow for error messages but starts at a reasonable compact size. NO `overflow-hidden`.

5. **Last resort: accept that the iframe is taller than ideal but DO NOT clip it.** Better an aesthetically-imperfect form than one that hides validation errors.
