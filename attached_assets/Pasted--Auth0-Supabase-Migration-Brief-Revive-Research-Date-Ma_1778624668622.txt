## Architecture Decisions (already confirmed — do not change)

1. **Keep Express sessions.** Do NOT switch to Supabase JWTs or implement RLS. Supabase is only replacing Auth0 as the login front door. The existing Express session pattern stays intact.

2. **Custom login form.** Do NOT use Supabase's generic Auth UI component. Build/adapt a custom login form that matches our brand.

3. **Lazy-on-first-login ID migration.** Do NOT pre-create Supabase accounts or run a bulk migration script. Existing users get migrated when they first log in post-cutover (details below).

4. **Keep `users.id` column as varchar.** Do NOT change to UUID type. This handles both legacy `auth0|xxxxx` IDs and new Supabase UUIDs during the transition period.

5. **Auth methods supported:** Google OAuth and email/password. Both must work.

## Step 3: Create Auth Callback Page

Create a route at `/auth/callback` that handles the OAuth redirect:

```javascript
// src/pages/AuthCallback.jsx (or equivalent)
import { useEffect } from 'react'
import { useNavigate } from 'react-router-dom'
import { supabase } from '../lib/supabaseClient'

export default function AuthCallback() {
  const navigate = useNavigate()

  useEffect(() => {
    const handleCallback = async () => {
      const { data: { session }, error } = await supabase.auth.getSession()

      if (session) {
        // Send session info to Express backend for sync
        const response = await fetch('/api/auth/sync', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          credentials: 'include',
          body: JSON.stringify({
            supabaseUserId: session.user.id,
            email: session.user.email,
            name: session.user.user_metadata?.full_name || session.user.email,
            avatar: session.user.user_metadata?.avatar_url || null
          })
        })

        if (response.ok) {
          navigate('/')  // or wherever logged-in users should land
        } else {
          console.error('Auth sync failed')
          navigate('/login?error=sync_failed')
        }
      } else {
        navigate('/login?error=no_session')
      }
    }

    handleCallback()
  }, [navigate])

  return <div>Completing login...</div>
}
```

## Step 4: Update Express Backend — `/api/auth/sync`

This is the critical endpoint. It must handle two cases:

### Case A: Existing user (has an `auth0|` prefixed ID in the database)

When an existing user logs in for the first time post-migration:

1. Receive the Supabase user info (UUID, email)
2. Query: does a user with this email exist with an `auth0|` prefixed ID?
3. **If yes:** Run the ID swap as an **atomic transaction** across ALL 13 tables that reference the user ID
4. Set the Express session with the new Supabase UUID
5. Continue normally

### Case B: New user (no existing record)

Normal new-user creation flow using the Supabase UUID as the user ID.

### The ID Migration Query (atomic transaction)

**All 13 tables that reference user ID must be updated in a single transaction.** Identify every table with a foreign key or column that stores the user ID. From previous audit, these include (verify this list is still current):

- `users` (primary key)
- `orders`
- `affiliate_accounts`
- `research_profiles`
- And 9 others identified in the original table audit

```javascript
// Pseudocode for the ID swap — adapt to your ORM/query pattern
async function migrateAuth0User(supabaseUuid, email) {
  const existingUser = await db.query(
    'SELECT id FROM users WHERE email = $1 AND id LIKE $2',
    [email, 'auth0|%']
  )

  if (!existingUser) return null  // not a legacy user

  const oldId = existingUser.id

  await db.transaction(async (trx) => {
    // Update every table that references the user ID
    // ORDER MATTERS: update foreign key tables BEFORE the primary key table
    await trx.query('UPDATE orders SET user_id = $1 WHERE user_id = $2', [supabaseUuid, oldId])
    await trx.query('UPDATE affiliate_accounts SET user_id = $1 WHERE user_id = $2', [supabaseUuid, oldId])
    await trx.query('UPDATE research_profiles SET user_id = $1 WHERE user_id = $2', [supabaseUuid, oldId])
    // ... repeat for all other tables ...

    // Update the users table LAST
    await trx.query('UPDATE users SET id = $1 WHERE id = $2', [supabaseUuid, oldId])
  })

  return supabaseUuid
}
```

**Critical:** This migration runs ONCE per legacy user on their first login. After the ID swap, they're a normal Supabase user going forward. Add a check so it doesn't attempt the swap again on subsequent logins.

## Step 5: Auth State Listener (Frontend)

Replace Auth0's session check with Supabase's auth state listener:

```javascript
import { supabase } from '../lib/supabaseClient'

// Listen for auth state changes (login, logout, token refresh)
supabase.auth.onAuthStateChange((event, session) => {
  if (event === 'SIGNED_IN' && session) {
    // User is logged in — sync with backend if needed
  }
  if (event === 'SIGNED_OUT') {
    // User logged out — clear frontend state
  }
})

// Check current session on page load
const { data: { session } } = await supabase.auth.getSession()
```
