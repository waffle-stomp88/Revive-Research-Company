Good calls. Let me think through this carefully because there's a real architecture question.

Two ways to handle the confirmation email:

Option A: Use the SAME "Restock Queue" autoresponder pipeline

The OOS signup adds the user to "Restock Queue" immediately as a "pending" contact, which triggers your existing autoresponder. But that's the SAME email that fires at actual restock time. So the user would get the restock email immediately upon signup, which is wrong.

This doesn't work.

Option B: Separate autoresponder + separate Zoho list

Create a new Zoho list called "Restock Signups" (or "Restock Confirmations"). When someone signs up for OOS notification:

Backend saves to Neon stock_notifications (already happens)
Backend ALSO adds them to "Restock Signups" Zoho list with PRODUCT_NAME and PRODUCT_URL custom fields
Autoresponder bound to "Restock Signups" fires the confirmation email immediately
Then later, when the product actually restocks, your existing flow adds them to "Restock Queue" which fires the restock email.

Two separate lists, two separate autoresponders, two separate emails. Clean architecture.
